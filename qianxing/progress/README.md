# 潜星计划 V2｜六项统一探索记录与体验反馈

开发批次：2026-10-29。公网计划入口：https://panxiangbin.github.io/pan/qianxing/progress/

## 功能
- 保留原有极简首页和108项目录，只增加“我的记录”文字入口，不加复杂帐号/管理后台。
- 独立连接现有6项V2：02视觉观察、06绘画、45沟通、52组织领导、72机械、77数据分析。其他102项保留旧版，不擅自标记成新版已完成。
- 正式点击各项“开始”后只更新共享进度状态。完成最后报告时写入实际完成项数、总项数、跳过数、完成时间与本次会话标识。
- 报告可能被重复渲染；使用同一会话标识去重，一轮任务不反复增加完成次数。开始新一轮会显示“进行中”，但保留此前已体验次数。
- 统一记录页提供按项目的可选反馈：难度（偏简单/合适/偏难）、操作清晰度、最多240字的“最需要优化的地方”；这些并不是正式测评评分。
- 有反馈时显示简短概览：偏简单、偏难、不清楚的项目数量，建议优先复查的项目名称。
- 自愿导出汇总JSON、新浏览器手动导入、明确确认后仅清空共享汇总。原模块本机画作、笔画、个人作答、音视频素材及详细实验结果不被汇总复制或清除。
- 同一浏览器、同一个网站域名下共享localStorage；不同浏览器、设备或隐私模式不会自动同步。此前的V1/V2成绩不回填，因此新版本上线前做过的题不会自动显示为完成。
- 本功能不含联网发送接口、不生成个人账号、不向后台上传数据；用户主动导出的汇总JSON可包含其自愿填写的文本反馈，须由用户自行保管。
- 页面没有“天赋总分”或排名，不把六种领域的行为强行合成同一量尺。

## 技术文件
- progress/tracker.js：安全白名单模型（固定6 ID、schema 1、允许的反馈枚举、文字和数字长度约束）、模块开始/完成与单会话去重、本地导入导出与清理。
- progress/app.js：六项列表、状态与时间、按模块反馈、难度概览、隐私/导出/导入/清除交互。
- progress/index.html / style.css / favicon.svg：简单、自适应的页面。
- 在6个V2入口页增加共享tracker.js脚本；分别在启动与报告生成位置加入一条轻量汇总调用，原项目保存机制维持不变。
- qianxing/index.html、qianxing/explore/app.js：只新增一个小的“我的记录”入口。
- 视觉/机械等未提供favicon的页面补充本地SVG图标，解决浏览器默认/favicon.ico导致的404资源警告。

## 验收路径
- tracker_test.mjs：18/18项基础数据约束、会话去重、输入导入白名单及不影响旧项目数据。
- progress_browser_qa.py：10/10组Edge真实浏览器，包括六项点击开始、完整视觉九轮结束、存储去重、XSS文本转义、手动反馈保存、汇总JSON导出/导入、不覆盖绘画项目、移动390px和无资源错误。
- qa_modules/qa_6.py：绘画13/13组（额外核实结束时汇总写入）
- qa_modules/qa_45.py：沟通9/9组（额外核实结束时汇总写入）
- qa_modules/qa_72.py：机械8/8组（额外核实结束时汇总写入）
- qa_modules/qa_77.py：数据10/10组（额外核实结束时汇总写入）
- qa_modules/qa_52.py：领导10/10组（额外核实结束时汇总写入）
- 全部网页验收脚本均调用现有真实互动，而不是直接伪造“完成”记录。
- 旧版测试脚本在下载后退出无头Edge时，偶有TargetClosedError工具进程清理日志；独立QA结果JSON在该阶段前已经写出。

## 科学与用户体验边界
- “已体验”和“做完项目”只表明用户完成过网页流程，不代表通过专业测量，更不代表某方面有先天天赋。
- 用户填写“偏难/偏简单”只是主观体验，不能据此自动改变全体用户的题目难度。后续应根据真实多人试玩、问题复现、题本质量与公平性进行修订。
- 统一记录不是跨设备账号/知识库或后端数据库。不会读取旧版使用历史，也不会被本功能自动备份到云端。

## 下一步
有实际试玩者自愿提交汇总JSON后，再按“偏简单/有障碍”筛选项目，针对单项做真实的题本难度和交互改进，而不是批量替换标题复制任务。真正科学有效的能力测评还需常模、信度、效度、等价平行题和公平性研究。
